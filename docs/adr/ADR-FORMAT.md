# ADR 规范

ADR 只记三类同时成立的决定：**难逆**、**无上下文会让人惊讶**、**当初真有过替代方案**。容易回退的不写；不令人惊讶的不写；没有真实替代方案的不写。当前结构、语义归属与读数不进 ADR：它们分别住 `docs/architecture.md`、测试与代码。

## 文件与编号

- 放在 `docs/adr/`，命名 `NNNN-slug.md`（顺序编号 + 短横线小写 slug）。
- 编号只追加、不复用、不跳号。
- 一篇只回答一个决定。一个决定需要多处改动，仍只写一篇；两个决定互相牵连但可分开翻案时，写两篇并互链。
- 每篇必须在 `docs/adr/README.md` 恰好出现一次；索引必须覆盖全部 ADR 文件。

## 状态

只允许以下形态：

- 完全有效：`Status: accepted`
- 完全被取代：`Status: superseded by NNNN`
- 部分被取代：`Status: accepted`，紧跟一行 `Superseded in part by: NNNN（被取代的范围）`

`Status` 行不带日期、括号补充或批次号；日期留在 git。部分取代必须写清范围，索引同样注明；不要把部分取代写成完全取代，也不要靠正文备注代替状态行。

## 结构

每篇至少要有：

```md
# 决策式标题

Status: accepted

导语 1–3 句：背景一句 + 决定一句 + 理由半句。
```

标题读完就要知道结论。按需增加章节，同一篇内保持命名一致：

| 章节 | 什么时候加 |
| --- | --- |
| `## 背景` / `## 动机` | “为什么”一句话装不下：多股作用力、要澄清的误报、历史包袱。 |
| `## 决定` | 决定多于一件互相牵连的事，或需要分条展开约束。 |
| `## 边界` | 明确不做什么、哪些语义仍归别的家，防止下一步改错地方。 |
| `## 后果` | 改动横跨多模块，读者需要知道波及面。 |
| `## 被否方案` / `## 被否掉的替代` | 拒绝本身需要论证、不记会被重提时。 |
| `## 代价` / `## 权衡` | 接受这个决定要付出什么，以及为什么仍值得。 |

轻决策允许只有标题、导语、被否方案与 `锚点：`。不要为了凑章节写空段。

## 锚点

每篇 ADR 末尾必须有 `锚点：` 一行。判据是**读者下一步能打开什么**：

- 实现符号（文件名 + 符号名）；
- 钉住它的测试；
- `docs/architecture.md` 的章节或另一篇 ADR。

不写行号；不指 `docs/superpowers/` 的过程产物；不拿 `.qoder/repowiki/` 当证据。锚点至少包含一个实现符号。

示例：

```text
锚点：`backend/pkg/errcode` 的 `Respond`；`backend/router/router_test.go`；`docs/architecture.md` 的「唯一主人清单」。
```

## 互引与取代

- 互引允许，用相对链接或 `ADR-NNNN-slug` 指路；开篇第一段必须自足，别把别篇正文抄过来当前情。
- 不引用仓外 ADR 编号：编号序列不对齐；溯源用提交 hash 或本仓可验证的锚点。
- 整篇不再成立：新写一篇，旧篇改为 `Status: superseded by NNNN`，正文保留；索引保留旧行并注明取代关系。
- 只翻其中一条：属事实漂移（文件改名、符号搬家、路径变化）就就地改正文；属决定反转就按整篇取代处理，不写“后来又改回……”的补丁串。
- 每篇 ADR 写完后做一次取代检查：搜索现有篇目，若有同一决定，更新或取代旧篇，不新建第二份。

## 写作纪律

- 当前真相只写现在时；背景里讲“当时为什么变”才用过去时。
- 不写日期、批次号、施工步骤或验收清单。
- 不抄会腐烂的读数与计数：构建产物大小、文件数、测试数都不进 ADR；要证据就指测试或代码。
- 点名仓内路径必须真实存在；改名或删除时同步改这里，或改指还活着的家。
- 代码与测试是最终真相；ADR 与代码冲突时改 ADR，并把长期成立的结论提炼回这里，而不是留在过程文档里。
