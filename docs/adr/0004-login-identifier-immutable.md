# 登录主标识不可变

`email` 作为登录主标识在注册时确定，此后不提供任何变更流程；可变性只属于展示用名（ADR-0002）。换邮箱服务商的用户出路是注销账号后重新注册（ADR-0005），而不是变更邮箱。

## 动机

ADR-0002 把可变性明确分配给了 `username`（"非空但可重复，注册时自动生成，可后改"），`email` 那栏只写"唯一、非空、登录主标识"，从未说可变。身份标识不可变也与账号根标识 `uid` 对称。

一旦允许变更，会牵出一整条依赖链：需证明对旧邮箱的占有（否则持有 access token 的攻击者可静默接管账号）、需验证新邮箱（否则改到失效邮箱就造出无法找回密码的死账号）、需额外的验证码命名空间与限流配额，并与防账号枚举姿态冲突（ADR-0006）。

## 决策

1. `email` 注册即确定，无变更接口。
2. `UpdateUserRequest` **保留** `email` 字段，但仅用于显式拒绝：传了与当前值不同的值 → 返回 `model.ErrEmailImmutable`（业务码 `A0113`，见 ADR-0001）；传了相同的值 → 幂等忽略。
   字段**不能删**——`ShouldBindJSON` 默认丢弃未知字段，删掉就无法察觉客户端传过 email，客户端会误以为修改成功。
3. `username` / `nickname` / `avatar` 的可变性维持 ADR-0002。
4. 换邮箱服务商的用户走注销重注册（ADR-0005）。

## 被拒方案

**邮件链接改邮箱** —— 给用户邮箱发一次性链接，点开后在网页里填新邮箱并验证。被拒原因：邮件里的链接必须是公网可访问的 HTTPS 地址，这给部署者加上了域名与证书的前置依赖。本项目是开源自托管项目，部署者可能只有 `localhost` 或局域网 IP，且该依赖配错时表现为**静默失败**——链接发出去了、邮件收得到、但打不开，用户只会认为功能坏了。

**裸 IP + IP 证书** —— Let's Encrypt 自 2026-01-15 起支持为公网 IP 签发证书，但强制 `shortlived` profile、有效期仅 160 小时，需要常驻的自动续期流水线；且邮件中出现裸 IP 链接是垃圾邮件的强特征，易被网关拦截。

**App Links 跳回 App** —— Android App Links 强制 HTTPS 与域名，同样不满足零部署依赖。

**旧密码兜底** —— 允许用旧密码代替旧邮箱验证码完成二次确认，以解救"原邮箱失效"的用户。被拒原因：二次确认的强度应对等于改密码，而改密码要求的是旧密码、改邮箱要求的是对当前邮箱的占有证明，两者不应互相替代。接受"原邮箱失效即无法变更"这一锁死。

## 后果

- 原邮箱失效（服务商倒闭、公司邮箱离职）的用户无法保留账号，只能注销重注册，历史数据不随之迁移。
- 此决策易逆转：将来增加变更流程不需要任何数据迁移。

## 冲突

与 ADR-0001 §4 冲突。该节将 `email` 描述为"注册时必填，作为密码找回唯一通道"，并未讨论可变性，本 ADR 在其基础上补充"不可变"。ADR-0001 的响应信封与双 token 部分不受影响。
