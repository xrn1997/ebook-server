# 文档规范

本文件回答“这条内容该放在哪、怎么写、什么时候更新或归档”。它不重复业务规则：某条语义归谁见 `docs/architecture.md` 的唯一主人清单；ADR 怎么写见 `docs/adr/ADR-FORMAT.md`。

**一条事实只住一个家**：当前事实源只写现在时；历史与变更过程只进 ADR、CHANGELOG 或 git；过程工件只留在工作区的 `docs/superpowers/`（整目录不入库），不作事实源。

## 1. 分层与职责

| 文档 | 只负责 | 不负责 |
| --- | --- | --- |
| `AGENTS.md` | 每次会话必须看到的读序、硬约束、必过门、环境坑 | 架构细节、命令全集、配置字段、提交规范、历史 |
| `CONTEXT.md` | 领域词汇、语义、`_Avoid_`、`_唯一实现_` | 实现步骤、决策理由、操作命令 |
| `README.md` | 用户可见事实：是什么、怎么装/用、API、配置、部署 | 维护者架构、测试门禁、决策理由 |
| `CONTRIBUTING.md` | 提交规范、PR 约定、提交前验证 | 构建细节、架构理由 |
| `TESTING.md` | 测试策略、测试结构、覆盖率口径、测试读数 | 构建/运行命令全集、架构理由 |
| `docs/architecture.md` | 模块地图、依赖方向、唯一主人清单、不变量 | 决策理由、操作步骤、历史、测试读数 |
| `docs/development.md` | 构建、运行、测试、生成、发版、环境坑、当前已知问题 | 架构理由、用户用法、决策历史 |
| `docs/adr/` | 一个决策的 why、边界、被否方案、后果 | 当前架构复述、计划、验收清单 |
| `docs/AGENTS.md` | 文档放置判据、写作规则、生命周期、评审清单 | 业务规则、架构细节 |
| `docs/agents/` | Issue、标签、领域文档的 agent 约定 | 本仓事实源 |
| `docs/superpowers/` | 设计说明、实施计划、调研报告与过程报告（只住工作区，整目录不入库） | 入库事实源、长期规格 |

## 2. 放置判据

- 每次会话看不到就会做错 → `AGENTS.md`。
- 用户装、用、数据在哪 → `README.md`。
- 词义与它的唯一实现 → `CONTEXT.md`。
- 当前结构、依赖方向、语义归属 → `docs/architecture.md`。
- 怎么构建、怎么验、怎么发版 → `docs/development.md`。
- 怎么提交、PR、发布边界 → `CONTRIBUTING.md`。
- 测试策略与读数 → `TESTING.md` 与测试代码。
- 为什么这么定、否掉了什么 → `docs/adr/`。
- 进行中的设计、计划、评审 → 工作区的 `docs/superpowers/`（不入库）；完成后把长期成立的部分提炼进 ADR、architecture 或 development，其余随工作区消失。
- 拿不准时按“读者在什么场景会打开它”选层。

## 3. 写作规则

1. 当前事实源只写现在时；历史、变更过程、旧方案只进 ADR、CHANGELOG、git 或过程文档。
2. 一个事实只有一个家；`docs/architecture.md` 的唯一主人清单是语义归属的唯一清单，别处只链接。
3. 代码与测试是最终真相；文档与代码冲突时改文档，并顺手改回现状。
4. 引用仓内路径用相对路径；点名的路径必须真实存在。docscheck 只豁免三类：整篇被取代的 ADR 保留正文当历史（不查路径存在性，见 §4）；记录删除决策或历史时可点名已删路径，但必须紧接标注「（已删）」；构建产物与运行时目录（`build/`、`frontend/dist/`、`logs/`、`uploads/` 等）不是仓库内容，不做存在性检查。
5. 不写行号（文件名后跟冒号和数字的形态会随任何一次编辑漂移）；要指实现就指符号锚。
6. 不抄会腐烂的读数与计数；需要证据就指测试或代码。
7. 注释与文档承担为什么、口径、裁决、证据，不承担代码细节；自测问题：这句删掉，读者丢的是“为什么”还是“怎么做”？只丢后者就删或升高度。
8. 词汇优先：新概念先进 `CONTEXT.md` 并点名 `_唯一实现_`，再写代码。
9. ADR 的写作、状态与取代规则住 `docs/adr/ADR-FORMAT.md`；一篇 ADR 只回答一个决定。
10. 根 `AGENTS.md` 预算 ≤ 8,000 字符；超限按“搬迁 → 压缩 → 提额并说明”处理，提额必须在提交信息里写理由。
11. 过程工件不进仓库：`docs/superpowers/` 整目录被 .gitignore 排除，只住工作区；长期成立的结论提炼进 ADR、architecture 或 development，其余不落库。
12. 引用外部文档原文不得改写；自家表述可直接改，引用只能在其之外另加读法说明，否则等于伪造出处。

## 4. 生命周期

- **ADR**：编号只追加、不复用；每篇紧跟标题写 `Status:`；部分取代用 `Superseded in part by: NNNN（范围）`；每篇在 `docs/adr/README.md` 恰好出现一次；正文只写当前真相，日期留在 git；整篇翻案新写一篇并标旧篇，事实漂移就地改。整篇被取代（`Status: superseded by NNNN`）的保留正文当历史，其中的仓内路径不要求仍然存在——docscheck 对这类文档豁免路径存在性检查，其余文档一律照查。
- **当前事实源**（`README.md`、`CONTEXT.md`、`docs/architecture.md`、`docs/development.md`、`docs/AGENTS.md`）：语义、结构、词汇或操作变化时同批更新；不写历史。
- **README**：用户可见事实变化时更新；配置样例、API 端点与部署方式同步。
- **CONTRIBUTING**：提交信息、PR/Issue 约定、提交前门或发版边界变化时同批更新；构建步骤仍住 `docs/development.md`。
- **CHANGELOG**：只在发版时追加已发布版本；写用户可见变化与升级注意，未发布改动不预写；逐提交明细留 git。
- **过程工件**：只住工作区的 `docs/superpowers/`（整目录不入库）；任务完成时把长期成立的结论提炼进 ADR、`docs/architecture.md` 或 `docs/development.md`，其余随工作区消失。
- **生成快照**：自动生成的 wiki/报告类目录整棵树重新生成，不逐文件修；与代码冲突时以代码为准，不把生成结论抄进手写文档。
- **文档与分层门禁**：随 `go test ./...` 运行；`backend/internal/docscheck` 检查常驻文档与 ADR，`backend/internal/archtest` 检查 Go 依赖方向。

## 5. 评审清单

文档改动提交前自查：

- 这条事实的家是否唯一？别处是否还有旧副本？
- 当前事实源里是否混进了历史、计划或“已改为”的口吻？
- 改动的路径、相对链接、ADR 编号是否都还活着？
- ADR 的 `Status:`、索引与 `锚点：` 是否齐全？
- 根 `AGENTS.md` 是否仍在 8,000 字符预算内？
- 过程工件是否只留在工作区的 `docs/superpowers/`、没有冒充当前事实？
- `CONTEXT.md` 新增或改动的 `_唯一实现_` 符号是否现查得到？
